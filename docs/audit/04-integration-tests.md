# 车载 Linux 最小接入与验证方案

## 第一阶段，有线替换现有蓝牙

1. STM32 保持原固件。拆下或断开蓝牙模块的 UART，使用电平已核实的 USB-UART 接 Linux。USB-UART TX 接 PA1，RX 接 PA0，共地。若用 Linux 板载 UART，先确认电平和设备树串口配置，关闭该口串口控制台。供电按实际板卡规格独立核对。适配器 VCC 保持断开，避免反向供电。禁止在同一 RX 上并接蓝牙 TX 和 Linux TX，也不要接 RS-232 电平。依据 MSP:431–456；M:521–540；BOM A15:G16。参考 [ST Nucleo-64 UM1724](https://www.st.com/resource/en/user_manual/dm00105823-stlink-v2-in-circuit-debugger-programmer-for-stm8-and-stm32-stmicroelectronics.pdf)。
2. Linux 以 115200 8N1 独占设备，优先使用稳定的 /dev/serial/by-id 路径。可用现有 PC 脚本在有图形环境下验证，或写一个轻量串口进程复用相同协议。开机先发 STOP 并持续读 POSE、LIDAR、TIME；IMU 等待以台架观察或调试变量确认。原协议没有 IMU ready 字段，固定延时不能当就绪判据。目标只发一次，每条坐标加换行。反复发送坐标会使已有路线失效并重新规划。C:136–172、406–448、570–638；PC:12–15、33–49、51–78。
3. Linux 端保存目标文本、单调时钟、接收原始行和解析结果，按状态观察跟踪、停止、到达。原协议没有 ACK 或命令号，不能凭一条 state=2 确认刚下发的任务完成。保留物理断电操作。此阶段做架空车轮和低速单目标演示，定位仍由 STM32 推算。C:151–155、586–592、688–769。

接线和传输验证留在 UART4。USART3 保留专给雷达。NUCLEO 的 ST-LINK VCP 如需接收命令，需要另配和改线。原代码只把雷达统计送给 Linux，且 115200/8N1 的理论有效字节率约 11.52 kB/s，无法透明转发 460800/8N1 满速的约 46.08 kB/s 数据。需要 Linux 直接处理整圈时，按实际雷达接口接到 Linux 的独立端口，或另设计 MCU 传输；同一雷达只允许一端发送控制命令。M:521–574；C:112–172、276–343。

## 第二阶段，最小固件补强

保留 PWM、编码器、IMU 任务和 UART4 配置。以下为后续实现建议，当前审计未改代码。安全测试通过之前使用架空台架。

| 位置 | 计划修改及验收点 |
|---|---|
| C:254–274、550–604 | 保留换行帧，增加版本、序号及 ACK/ERR，增加专用心跳或有效期，校验字段和范围。错误产生时失效旧命令和待规划路径。STOP 优先、幂等，并对其响应。旧版坐标入口可作为明确启用的调试兼容模式 |
| C:649–769 | 所有动作由 Control 统一执行状态机。加上电锁止、显式启用、失联超时、STOP/故障锁止、复位禁自动续跑；运动控制与心跳分别计时。按实测最坏延迟及制动距离设超时。必要时用独立驱动使能或硬件急停让 MCU 卡死也能切断电机 |
| C:90–172、439–443、762–766 | 遥测加最近命令序号、ready、故障原因、编码器增量和采样 tick。POSE 读取使用一致快照，记录发送失败。Linux 监控收到的年龄、序号与状态，遇重启重新建立会话 |
| C:606–638、704–765 | 先验证单个目标。如果改为 Linux 规划，STM32 增加单段或路点列表入口，避开每次自动插入 L 形拐点的旧命令。Linux 维护棋盘状态和坐标，STM32 负责定时跟踪及停机。需要显式终点朝向或速度控制时增加对应入口和有单位的反馈 |

棋盘位姿约定应提前固定。示例可沿用现有传感器朝向约定，以 m、rad 表示内部运动数据，经已测棋盘原点和旋转换算棋格坐标。格距、场地幅宽、速度上限及终点误差验收值由赛题和实测确定，当前源码没有这些参数。C:14–22、550–567、658–686。

## 验证原版本

截至审计，原包 313 个归档文件与解压件逐项哈希一致。PC 脚本通过 Python AST 语法解析。16 MHz 下的定时器计算及正反向 16 位计数回绕算例已核对。交付 ELF 为 ARM 32 位小端，入口 0x080040B9，编译器标记 GNU Tools for STM32 12.3.rel1 / GCC 12.3.1，是既有产物。在工程副本调用 build-check.ps1 时，本机 CubeIDE 自带 ARM GCC 14.3.rel1 启动即报无效的系统 DLL 重定位，未走到编译或链接。本次没有烧录、实车测量或实际重放。旧报告的实测表也为空。R:45–55；build-check.ps1:4–20；Debug/Core/Src/subdir.mk:3；Debug/AMR_NEW_CodingDay4.elf 的 ELF 头及 .comment 节。

按下列顺序进行，除另开版本针对补强项目外，统一使用原代码。将固件哈希、编译器版本、实际接线、车轮及地面、采集原始文件和结果表一并记录。
